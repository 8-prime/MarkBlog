## Project Overview

MarkBlog is a full-stack blog platform. The Go backend serves both a public-facing blog (HTML via `templ`) and a REST API consumed by a React admin dashboard frontend.

## Development Commands

### Backend (Go)

Run from `backend/`:
```bash
go run cmd/api/main.go       # Start the backend (port 3000 in dev)
go build ./...               # Build all packages
go test ./...                # Run all tests
```

Code generation (run from `backend/` after changing SQL queries or templates):
```bash
sqlc generate                # Regenerate Go types from queries.sql
templ generate               # Regenerate Go from .templ files
goose -dir internal/database/migrations sqlite3 ../data.db up  # Run migrations
```

### Frontend (React)

Run from `frontend/`:
```bash
pnpm dev                     # Start Vite dev server (proxies /api to localhost:3000)
pnpm build                   # Type-check + build to dist/
pnpm lint                    # Run ESLint
```

### Docker

```bash
docker build -t markblog .           # Multi-stage build (backend + frontend → Alpine)
docker compose up                    # Run with docker-compose.yml
```

## Architecture

### Request Flow

- **Public blog** (`/`, `/articles/{id}`, `/sitemap.xml`): Go handlers render HTML using `templ` templates and serve it directly.
- **Admin UI** (`/admin/*`): Go serves the compiled React SPA from `FRONTEND_DIR`. The React app calls the `/api/*` endpoints.
- **API** (`/api/articles`, `/api/images`, `/api/user`, `/auth/*`): JSON REST endpoints. Auth is optional (controlled by `AUTH_ENABLED` env var); when enabled, routes are protected by `authMiddleware`.

### Backend Structure (`backend/internal/`)

- `cmd/api/main.go` — entry point; loads config, wires dependencies, starts server with graceful shutdown
- `models/configuration.go` — all config comes from env vars (loaded from `.env` in dev via `godotenv`)
- `server/routes.go` — all route registration (chi router)
- `services/` — business logic: `ArticleService` (CRUD + file I/O), `PublisherService` (scheduling/publishing workflow), `RendererService` (Markdown → HTML)
- `handlers/` — thin HTTP handlers that call services
- `database/` — sqlc-generated types + query functions; migrations run automatically on startup via goose
- `middleware/` — session-based auth middleware using `markbates/goth` (Google OAuth2)
- `templates/` — `templ`-generated HTML templates for public pages

### Database

SQLite via `database/sql`. Schema is defined by goose migrations in `backend/internal/database/migrations/`. SQL queries are written in `backend/queries.sql` and code-generated by `sqlc` into `backend/internal/database/`. **Do not edit the generated files** (`db.go`, `models.go`, `query.sql.go`) directly.

Key tables: `articles`, `tags`, `article_tags` (M2M), `article_reads` (view analytics).

The article publishing workflow uses three nullable timestamp columns: `published_at`, `scheduled_at`, `deleted_at`.

### Frontend Structure (`frontend/src/`)

- `App.tsx` — React Router route definitions
- `api/endpoints.ts` — all API calls (fetch wrapper functions)
- `models.ts` — TypeScript types mirroring backend models
- `hooks/auth.ts` — `useAuth` hook (queries `/api/user`)
- `AuthGuard.tsx` — wraps protected routes; redirects to login if unauthenticated
- `pages/` — top-level page components
- `components/` — reusable UI components including the markdown editor

Data fetching uses **TanStack React Query**. The Vite dev server proxies `/api` to `localhost:3000`.

## Environment Configuration

Backend reads from `backend/.env` in development (`IS_PROD=false`). Key variables:

| Variable | Purpose |
|---|---|
| `IS_PROD` | Skips `.env` loading in production |
| `AUTH_ENABLED` | Enables Google OAuth2 auth middleware |
| `CONNECTION_STRING` | SQLite DB path (defaults to `:memory:` if unset) |
| `ARTICLES_DIR` | Directory where markdown article files are stored |
| `IMAGES_DIR` | Directory for uploaded images |
| `FRONTEND_DIR` | Path to built React app (`frontend/dist`) |
| `HOSTING_URL` | Base URL (used to build OAuth callback URL) |
| `ADMIN_EMAIL` | Email allowed to authenticate as admin |
